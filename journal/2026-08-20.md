#### The miss was cadence, not judgment

entry.md specifies re-checks **every 5 minutes**. Actual spacing today:

`9:37 → 9:48 → 9:55 → 10:08 → 10:22 → 10:33 → 10:46 → 10:59 → 11:17 → 11:30 → 11:42 → 11:54`

Gaps of **7, 11, 12, 13, 13, 13, 14, 18** minutes — a median of about 13. Each cycle takes several minutes to execute (guards, scans, bars, quotes, logging, commit) and the next is armed for +6 or +7 minutes *after* that work finishes, so the effective cadence is roughly **2.5× the specified interval**.

A §1.3 qualification that lives for one 5-minute bar therefore has roughly a **40% chance of being observed at all**. Today it landed in a gap: the qualifying bar closed at 11:45, this cycle fired at 11:53, and by then two further bars had invalidated it.

1. **Arm the next re-check before doing the cycle's own logging and committing**, so the interval is measured from the start of a cycle rather than the end. That alone recovers most of the drift at zero cost.
2. **Evaluate the last N bars for qualification, not just the current one** — if any bar within the last two closed with all four §1.3 legs satisfied *and* the base tape still holds live, treat the signal as live. This is the honest fix, since the thesis ("volume-confirmed continuation") does not evaporate in five minutes; only the current-bar snapshot does.
3. Tighten the arming interval to 3–4 minutes to compensate for execution time.

Option 2 needs care — it must not become a licence to act on stale data. The condition would be that the *qualifying* bar is recent AND the base tape is confirmed live at decision time, which today would still have declined at 11:54 because the up-close structure had already broken.

### Correction to the 13:35 note — the mechanism is stickiness, not directional error

At 13:35 I recorded the option mid as moving *opposite* its underlying and framed it as the quote being directionally wrong. This cycle refines that, and the refinement matters because it changes the fix.

At 13:41 the bid and ask printed **exactly 0.910 / 0.940 — identical prices to 13:35**. Only the sizes moved (157 → 170 on the bid, 40 → 62 on the ask). The underlying meanwhile fell 10.825 → 10.770, −0.51%, which at delta 0.595 should have moved the option −0.033. It moved 0.000.

Across the two cycles together:

| | 13:29 | 13:35 | 13:41 |
|---|---|---|---|
| MARA | 10.7785 | 10.825 (+0.43%) | 10.770 (−0.51%) |
| $10.50C mid | 0.955 | 0.925 (−3.1%) | 0.925 (0.0%) |

The underlying round-tripped to −0.08% net; the option went −3.1% then flat. So the quote is not tracking *wrongly* — it is **updating in discrete jumps and sitting still through sub-1% underlying moves**. The 13:29 → 13:35 drop was the mid catching *down* after having been sticky high at 0.955, not a genuine inversion.

The corrected finding: **on a THIN contract the option mid is stale in steps, and a single-cycle sample of it can look directionally wrong.** The hazard for monitor.md is the same either way — every exit level keys off the option mid, so a trailing stop can fire on a catch-down step that has nothing to do with the thesis — but the remedy is better aimed at staleness than at direction. Requiring a confirming underlying move before acting on an option-price stop still addresses it; keying the ratchet off the underlying and using the option only for execution addresses it more directly.
